# fenrirealm-monitor — Agent Instructions

One static Go binary ingesting exceptions, logs and performance profiles for every first-party Fenrir Realm stack (Laravel backend = PHP, SvelteKit front/admin = JavaScript). UI is server-rendered html/template with zero runtime JS.

### Project Invariants & Reusable Conventions

- **Templates are baked at build time**: pages live in `internal/web/templates/*.html` behind `go:embed` — after editing any template or handler-embedded asset, `go build` and restart the process before browser verification; a running old binary serves stale UI and will waste a verification round (iniznet/fenrirealm-tracker#148).
- **The dashboard IA is two sections on one param dialect (iniznet/fenrirealm-tracker#205 M6.1)**: Errors (`/errors`, tabs Issues|Logs) and Performance (`/performance`, tabs Endpoints|Traces|Hotspots) are the nav; `/issues`, `/logs`, `/profiles`, `/slowest`, `/traces`, `/traces/{id}` keep serving the same handlers (Expand/Contract). `parseToolbar` in `internal/web/params.go` is the ONLY reader of `project`/`range`/`env`/`org` and `toolbar.Link` the only link builder — a second reader or a hand-built query string reintroduces the dialect drift the M6.1 pre-mortem names, where a link that drops one field silently resets the reader's filters. Every page must render with zero params (defaults: all projects, 24h, all envs) and an unknown/empty `tab` or `range` resolves to the section default, never a 404; `internal/web/m61_test.go` pins all three. New percentile/aggregate reads carry a time bound PLUS a row ceiling (the 70100 wedge class), and the footer health strip reads LIVE ingest counters (`Shaper.Rejections`, `KeyGate.Rejections`, `KeyGate.UnknownAdmits`) — never a cached number, because the reader is asking "why is my data missing?".
- **Tenancy is additive and budgets are per project (iniznet/fenrirealm-tracker#205 M6.2)**: an `orgs` + `org_members` pair and an additive `projects.org_id` (default org 1) group projects without ever re-keying the ingest surface — assignment must never touch `projects.key`/`ingest_key`, and `ProjectsInOrg` must keep unioning the `projects` table with the event tables, because the TCP Monolog leg and direct store writes bypass the ingest gate and a log-only producer legitimately has no row (dropping the union silently hides producers from the toolbar). `PruneProfiles` is partitioned by `project_key` — a single global keep-window let one noisy producer evict every other org's profiles and traces; keep every retention statement chunked and window-ranked. Org roles (`owner`/`admin`/`viewer`) are seeded from the M4 users table (`SeedMemberships`, plus the same grant inside `CreateUserIfNone` and `ResetAdminPassword`), an unknown role is rejected rather than stored, and **roles are not yet an authorization boundary**: the org selector scopes the reader's projection only.
- **Operator settings are DB-backed with the flags as import-once defaults (iniznet/fenrirealm-tracker#205 M6.3)**: `SeedSettings` writes a key ONLY when absent, so a value an operator saved at `/settings` must survive every restart and redeploy — never re-seed unconditionally, and never let a flag override a stored row. `settingBounds` is the single validation table: a key absent from it is NOT writable (a typo in the UI must not mint a setting nothing reads), every submitted value is validated BEFORE any is stored so a save can never half-apply, and the numeric readers (`SettingInt`/`SettingFloat`) degrade to their fallback on a corrupted row rather than taking the retention loop down. The retention loop re-reads `retention_days`/`prune_interval_minutes`/`profiles_per_project`/`occurrence_cap` from settings each cycle (`MaxOccPerMin` is an atomic for exactly that reason — a plain int field raced the loop against per-event reads); the shaper's rate/burst are built at boot and are labelled `restart` on the page. Sampling rates, the Sentry DSN and the log-channel list are PRODUCER-side env, not monitor settings.
- **`profiles.trace_id` is the cross-service join key (#171/#180)**: request profiles carry a top-level `trace_id`; xhprof callgraphs carry `tags["trace_id"]` (the profiler ingest reads exactly that tag into the same column); `/traces/{id}` stitches legs into one waterfall — each downstream leg anchors at the parent's first span tagged `leg=backend` (start, so the child draws inside the fetch window), spans without `start_ms` keep the legacy sequential layout, and each leg's top self-time hotspots render inline under the waterfall. Spans store elapsed offsets from their own profile start, never absolute wall-clock.
- **`profiles.tree` carries the pruned call stack (#181)**: the xhprof ingest rebuilds the tree from the edge map (root `main()`, inclusive = edge wt, self = incl − Σ expanded children; recursion cycles and the depth cap fold into self); the profile ingest accepts a client-sent `tree` through the same caps — subtrees below max(1%·total, 2 ms) fold into the parent's self, >20 siblings collapse into an `(other ×N)` bucket, depth ≤12, and a >64 KB tree is dropped without losing the row. Profile + trace pages render a collapsible `<details>` stack; the flat hotspot list stays the fallback for tree-less rows.
- **M4 security surface (#157)**: dashboard pages are auth-gated by an HMAC session cookie (`-session-secret`; unset = per-boot key, sessions die on restart) with first-run `/setup` open only while `users` is empty — the first INSERT wins and setup locks forever. Logout and `-reset-admin <email>` push a per-user `sessions_valid_after` epoch that revokes older stateless cookies; `/up` and all ingest routes stay unauthenticated-by-design (keys below gate them). Login failures are throttled 5/15min per ip+email. Never serve the dashboard over plain HTTP at a public ingress without TLS.
- **Ingest keys are additive**: every project row may carry a rotateable `ingest_key` (set at `/keys`); requests must then present `Authorization: Bearer <key>` or `X-Monitor-Key` (constant-time compared). Projects without a key keep accepting legacy unsigned ingest — boot logs the count. Rotation AND revocation invalidate the cached gate decision in-process immediately (`KeyGate.Invalidate`); revoking (`/keys` Revoke button, `POST /keys/revoke`) drops a project back to unsigned legacy admission — the escape hatch when a producer cannot present a key. URL-native senders that cannot set custom headers (the xhprof extension posting from its endpoint userinfo) authenticate as HTTP Basic: the PASSWORD segment carries the key. The TCP 9913 leg has no header and stays unsigned.
- **Alerts are file-configured and inert without `-alerts-config`**: rules (new-issue, regression [auto-reopen + alert], count-window, p95-latency, heartbeat) evaluate on a tick against aggregates, never per-event; `alerts_log` records only successful sends, so a failed channel retries next tick and cooldowns (default 60m per rule+target) plus per-channel hourly/daily caps bound the storm. No alert UI in M4 (M6 settings pages).
- **Job, release and user-impact telemetry (#158, M5)**: `POST /ingest/{project}/job` batches runs into one aggregate row per (project, kind, name) via an optional `count` (queue producers window 60s in-process; commands ship per run because schedule:run is a short-lived process and the heartbeat rule reads `last_ok_at`); `job_stats` is bounded by name count and covered by retention. `releases` is HARD-CAPPED at the newest 100 rows per project on every insert. The heartbeat rule `{command, cadence_seconds, grace_multiplier}` (default ×2) never fires before monitor boot + one full window and re-alerts only past cooldown. `occurrences.user_id` stores the raw opaque id ONLY (Sentry `event.user.id` or top-level `user_id`) — never email/name; UI renders COUNT(DISTINCT) as "users affected". Crash-free per release is a CONSERVATIVE upper bound (full-volume errors ÷ sampled requests) and must always be labelled a sampled estimate (#158).
- **Ingest wire contracts are compat-locked**: `POST /ingest/{project}/sentry|profile|error|xhprof`, `/api/{project}/store|envelope` (Sentry SDK), `/api/profiler/store` (spiral profiler), TCP 9913 (Monolog newline-JSON) and `GET /up` must never change shape — producers live in other repos (Laravel `MonitorClient`, SvelteKit `lib/server/monitor.ts`) and ship against these paths (iniznet/fenrirealm-tracker#145).
- **Grouping fingerprints are frozen**: `store.ForException`/`ForLog` normalize volatile tokens; changing the algorithm re-groups every existing issue on deploy — treat both functions as release-pinned (iniznet/fenrirealm-tracker#141).
- **The store must stay bounded**: `RunRetention` (age-prune occurrences, cap 50/issue, keep newest 5000 profiles) runs on the background ticker from `cmd/monitor`; never delete issues (the defect list is the history), never run retention deletes in a request path, and keep every prune chunked — the SQLite connection is single-writer and shared with ingest.
- **Migrations are additive and idempotent**: new columns/indexes are applied at boot in `migrate()` and must ignore only `duplicate column`/`already exists` errors; never drop or rename (Expand/Contract).
- **CORS is opt-in**: only the first-party error/profile endpoints honor `-cors-origin`; browser preflight has its own `OPTIONS` registration because a POST pattern never matches preflight. Default off — server-only senders need no CORS headers.
- **UI stays hydrate-free**: server-rendered SVG (sparklines, waterfall, bars), meta-refresh only on the log stream, no client state — interactive JS belongs in the producer repos, not here.
- **Dashboard views compose from grouped passes, never per-project fan-out**: the all-projects dashboard draws every project's figures from `DashboardSummaries` (ONE windowed `occurrences JOIN issues` pass GROUP BY project/type/hour-bucket + two small issues-table passes + the index-driven per-project `RequestStats`) — re-adding a per-project `HourBuckets` loop re-walks the whole 24h range once per figure and put the dashboard at 28s under real volume (iniznet/fenrirealm-tracker#169). Lists that surface pain must default to pain order (`count DESC` for issues, total-time for profile routes), not recency.
