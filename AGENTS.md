# nightpost — Agent Instructions

One static Go binary ingesting exceptions, logs and performance profiles for every first-party Fenrir Realm stack (Laravel backend = PHP, SvelteKit front/admin = JavaScript). UI is server-rendered html/template with zero runtime JS.

### Project Invariants & Reusable Conventions

- **Templates are baked at build time**: pages live in `internal/web/templates/*.html` behind `go:embed` — after editing any template or handler-embedded asset, `go build` and restart the process before browser verification; a running old binary serves stale UI and will waste a verification round ().
- **The dashboard IA is two sections on one param dialect ()**: Errors (`/errors`, tabs Issues|Logs) and Performance (`/performance`, tabs Endpoints|Traces|Hotspots) are the nav; `/issues`, `/logs`, `/profiles`, `/slowest`, `/traces`, `/traces/{id}` keep serving the same handlers (Expand/Contract). `parseToolbar` in `internal/web/params.go` is the ONLY reader of `project`/`range`/`env`/`org` and `toolbar.Link` the only link builder — a second reader or a hand-built query string reintroduces the dialect drift the pre-mortem names, where a link that drops one field silently resets the reader's filters. Every page must render with zero params (defaults: all projects, 24h, all envs) and an unknown/empty `tab` or `range` resolves to the section default, never a 404; `internal/web/m61_test.go` pins all three. New percentile/aggregate reads carry a time bound PLUS a row ceiling (the 70100 wedge class), and the footer health strip reads LIVE ingest counters (`Shaper.Rejections`, `KeyGate.Rejections`, `KeyGate.UnknownAdmits`) — never a cached number, because the reader is asking "why is my data missing?".
- **Tenancy is additive and budgets are per project ()**: an `orgs` + `org_members` pair and an additive `projects.org_id` (default org 1) group projects without ever re-keying the ingest surface — assignment must never touch `projects.key`/`ingest_key`, and `ProjectsInOrg` must keep unioning the `projects` table with the event tables, because the TCP Monolog leg and direct store writes bypass the ingest gate and a log-only producer legitimately has no row (dropping the union silently hides producers from the toolbar). `PruneProfiles` is partitioned by `project_key` — a single global keep-window let one noisy producer evict every other org's profiles and traces; keep every retention statement chunked and window-ranked. Org roles (`owner`/`admin`/`viewer`) are seeded from the M4 users table (`SeedMemberships`, plus the same grant inside `CreateUserIfNone` and `ResetAdminPassword`), an unknown role is rejected rather than stored, and **roles are not yet an authorization boundary**: the org selector scopes the reader's projection only.
- **Operator settings are DB-backed with the flags as import-once defaults ()**: `SeedSettings` writes a key ONLY when absent, so a value an operator saved at `/settings` must survive every restart and redeploy — never re-seed unconditionally, and never let a flag override a stored row. `settingBounds` is the single validation table: a key absent from it is NOT writable (a typo in the UI must not mint a setting nothing reads), every submitted value is validated BEFORE any is stored so a save can never half-apply, and the numeric readers (`SettingInt`/`SettingFloat`) degrade to their fallback on a corrupted row rather than taking the retention loop down. The retention loop re-reads `retention_days`/`prune_interval_minutes`/`profiles_per_project`/`occurrence_cap` from settings each cycle (`MaxOccPerMin` is an atomic for exactly that reason — a plain int field raced the loop against per-event reads); the shaper's rate/burst are built at boot and are labelled `restart` on the page. Sampling rates, the Sentry DSN and the log-channel list are PRODUCER-side env, not monitor settings.
- **Ingest hardening for public ingress (0)**: the per-project token bucket is keyed on the `{project}` PATH SEGMENT, which an unauthenticated caller chooses — a distinct-name flood therefore minted a fresh full-burst bucket per name (so the per-project budget never engaged) while also auto-provisioning a permanent `projects` row and a permanent gate entry. Three ceilings close that, and the ORDER is the contract: `WithIngressGuard` runs OUTERMOST and is keyed on nothing the caller picks (one global bucket + one bucket per source address, both evicting to a cap), then `WithKeyGate`, then the per-project `WithShaper` innermost where it can only ever be a fairness limit. `ClientIP` must keep IGNORING `X-Forwarded-For` — the header is caller-controlled, so honouring it hands an attacker a fresh per-address bucket per request; behind a reverse proxy every request shares the proxy address, which is why the global bucket is the primary ceiling and `-ingress-ip-rate 0` switches the per-address leg off. First-sight unsigned admission is BOUNDED (`ConfigureAutoProvision`): past `-max-auto-projects` a new name answers 429 instead of growing the projects table, `-require-ingest-keys` refuses unsigned ingest outright (the endgame posture for a public ingress), and both increments are counted for the footer health strip. `UnsignedProjectCount` reaches the gate through the optional `projectCounter` interface so the `ProjectKeyStore` contract and its fixtures stay unchanged.
- **`profiles.trace_id` is the cross-service join key (#171/#180)**: request profiles carry a top-level `trace_id`; xhprof callgraphs carry `tags["trace_id"]` (the profiler ingest reads exactly that tag into the same column); `/traces/{id}` stitches legs into one waterfall — each downstream leg anchors at the parent's first span tagged `leg=backend` (start, so the child draws inside the fetch window), spans without `start_ms` keep the legacy sequential layout, and each leg's top self-time hotspots render inline under the waterfall. Spans store elapsed offsets from their own profile start, never absolute wall-clock.
- **`profiles.tree` carries the pruned call stack (#181)**: the xhprof ingest rebuilds the tree from the edge map (root `main()`, inclusive = edge wt, self = incl − Σ expanded children; recursion cycles and the depth cap fold into self); the profile ingest accepts a client-sent `tree` through the same caps — subtrees below max(1%·total, 2 ms) fold into the parent's self, >20 siblings collapse into an `(other ×N)` bucket, depth ≤12, and a >64 KB tree is dropped without losing the row. Profile + trace pages render a collapsible `<details>` stack; the flat hotspot list stays the fallback for tree-less rows.
- **Scheduled retention passes are set-based and issue-id RANGED**: `PruneIssueOccurrences` used to read EVERY issue id into memory and issue one DELETE per issue — O(issues) statements per tick on the single WAL writer, the 70100 wedge class. It is now ONE window-function DELETE per issue-id range (`pruneChunk` = 500), and `ArchiveStaleIssues` follows the same shape. Ranging rather than a global LIMIT is deliberate: the cap is PER ISSUE, so a global row limit would starve later issues while over-pruning earlier ones. Measured: 90,000 rows across 20,620 issues in 785ms via 42 statements.
- **The `issues` table is bounded by archiving, and archiving is reversible**: every distinct log message becomes an `issues` row (measured: 20,000 rows in one day of real volume), so `ArchiveStaleIssues` marks a row archived once retention removed its occurrences and it has not been seen since — leaves the live lists/counts, keeps its count history. **Both recorders must keep clearing `archived_at` on conflict**, or a returning defect stays hidden forever, which is worse than an unbounded table. The guard is on the dashboard READS (issue list, open/total counts, log levels, new-since-release, per-project overview) and must NEVER go on project/org DISCOVERY (`Projects`, `ProjectsInOrg`), or archiving could drop a project from `/keys` and lock an operator out of rotating its key.
- **`go test -race` cannot run on the Windows dev host, so it runs in CI ()**. There is no C compiler there, so the detector answers `-race requires cgo` — a silent gap if you only ever verify locally. The local substitute is `internal/ingest/concurrency_test.go`: meaningful because the Go runtime turns a concurrent map write into a FATAL error even without the detector, so a dropped lock fails loudly. That catches a lost lock and NOT races only the detector sees, which is why CI's ubuntu runner (which has gcc) owns `go test -race ./...`. Do not "fix" a local `-race` failure by disabling the CI step.
- **Go RAW-STRING SQL cannot take a concatenated constant**: `liveIssueFilter` was inserted into backtick SQL literals as `AND"+liveIssueFilter+"AND`, so the predicate reached SQLite as literal text and the issue list silently returned nothing — compiled fine, failed only in tests. Write the guard inline at each query. Prefer a test that asserts rows come back over one that asserts the string was built.
- **`HourBuckets` drives from `issues`, and the index that would have helped was REJECTED on measurement**: written as `FROM occurrences JOIN issues` the planner scanned occurrences by `seen_at` and read the clustered row per match for project/type — 213ms over a realistic 200k-occurrence day, the slowest dashboard query by an order of magnitude. Reversing the join lets it reach each issue's occurrences through the existing covering `(issue_id, seen_at DESC)` index, which carries `seen_at` itself: 213ms → 132ms at ZERO write-path cost. A new `(seen_at, issue_id)` index reached 87ms but cost 31% of ingest throughput and doubled two list queries, so it is not added. Measure before indexing the hottest table.
- **Hourly rollups are NOT built**: the phase was conditional on measured dashboard slowness and the numbers do not justify them (one query >100ms, the rest <30ms). Reopen only against a fresh `MONITOR_SCALE=1` run, with the write ceiling (6,500-9,500 events/s, single writer) in hand.
- **The licence is open-core and the grant boundary is explicit**: this server is AGPL-3.0 (verbatim `LICENSE`), the producer packages are MIT, and the managed control plane is a separate product outside this repo — the component list is `NOTICE`. The "every dependency is permissive" claim is kept true by a COMMAND rather than by prose: `go list -deps ./cmd/monitor` is the exact link set, it is strictly smaller than the module graph, and the graph's one MPL-2.0 module (`hashicorp/golang-lru/v2`) is provably not in the binary. Re-run that command when adding a dependency, because the prose cannot keep itself true. Publishing under this licence is the irreversible step (after the first outside contribution, relicensing needs every contributor's consent), and the DCO choice belongs before that, while the copyright holders are still only us.
- **The wire boundary is frozen in `WIRE_SPEC.md` and executable in `testdata/wire/`**: every ingest route has a golden vector (canonical payload + the assertion that it lands in the store) and `internal/ingest/wire_vectors_test.go` runs all of them against the real handlers, so spec drift fails a test instead of a request. Publishing v1 makes the boundary **additive-only** — new optional fields and routes, never a rename, because third-party ports are consumers we cannot redeploy on our schedule. Two vector findings are contract, not implementation detail: the stored SQL is a **fingerprint** (`id = 7` → `id = <n>`, so literals never survive into the store and `id = 5`/`id = 6` group), and a request with no trace context keeps an empty `trace_id` rather than inventing one. `DEPLOY.md` carries the operational half (install, reverse-proxy ingress, health contract, upgrade notes, recovery).
- **A public ingress requires `-require-ingest-keys`**: with ingest reachable from the internet, unsigned POST is an open door, so the ceilings exist to make the flood pointless rather than to make unsigned ingest safe. `DEPLOY.md` is the reference for the exposure checklist: TLS, expose `/ingest/*` and `/api/*` only, `-ingress-ip-rate 0` behind a proxy, per-project CORS at `/keys`.
- **Registration-required mode closes the other half of the same door**: `-require-registered` answers **401 unknown project** instead of `EnsureProject`-admitting, so the caller-chosen `{project}` name stops being a resource an attacker allocates; a project that already exists without a key stays admitted, which is the Expand/Contract path, so flipping the flag cannot break a running producer. It is the narrower refusal and pairs with `-require-ingest-keys` (which 401s unsigned traffic on projects that *have* a key). The flag defaults OFF in this repo on purpose — the product build flips it on at fork time — because deploying an existing install must never change its ingress posture without an operator saying so. The existence check fails **open** on a read error, exactly like a failed key lookup, so a transient store problem cannot blackhole producers.
- **Both caller-keyed ingest maps are bounded**: `keygate.seen` is a `knownSet` (cap 4096, oldest-half eviction) and the shaper's bucket map is capped, because both are keyed on a name the CALLER picks — an unbounded map there is the cross-tenant DoS the multi-tenant pitch cannot ship with. Eviction is harmless by design: an evicted name costs one extra decision, never a wrong admission. `UnknownAdmits` counts **auto-provisioning**, not first sight — a registered unsigned project needed no row, and counting it would inflate the very attack signature the counter exists to show (caught by test, not review).
- **A TLS-terminating proxy must declare itself with `-cookie-secure`**: the session cookie is `HttpOnly` + `SameSite=Lax` and `Secure` when the request itself is TLS (or when the flag says so), never inferred from `X-Forwarded-Proto` — that header is caller-controlled exactly like `X-Forwarded-For`, and trusting it would let a plain-HTTP request mint a cookie the browser then sends in the clear. The shipped image also sets `--session-secret-file /data/session.key` in its `CMD`, so a container install persists its session key inside the volume instead of logging everyone out on every deploy.
- **The session key and its persistence**: `-session-secret` wins; else `-session-secret-file` is read; else a random per-boot key is generated — and when a file IS configured the generated key is **persisted** (0600) instead of discarded, because the old random-per-boot default silently logged every admin out on each deploy. `randomSessionSecret()` must keep returning the key in the SAME hex form the file holds: returning raw bytes made the file a *different* key from the running one, so sessions still died on restart (caught by `TestResolveSessionSecretPersistsAcrossRestarts`, and proven live by a cookie surviving a restart).
- **M4 security surface (#157)**: dashboard pages are auth-gated by an HMAC session cookie (`-session-secret`; unset = per-boot key, sessions die on restart) with first-run `/setup` open only while `users` is empty — the first INSERT wins and setup locks forever. Logout and `-reset-admin <email>` push a per-user `sessions_valid_after` epoch that revokes older stateless cookies; `-reset-admin` writes the minted password to a 0600 file (`-reset-admin-out`, default `<db-dir>/admin-reset.txt`) and never logs it, because the container's stdout lands in the json-file log and would keep the credential for the log's whole rotation window; `/up` and all ingest routes stay unauthenticated-by-design (keys below gate them). Login failures are throttled 5/15min per ip+email. Never serve the dashboard over plain HTTP at a public ingress without TLS.
- **Ingest keys are additive**: every project row may carry a rotateable `ingest_key` (set at `/keys`); requests must then present `Authorization: Bearer <key>` or `X-Monitor-Key` (constant-time compared). Projects without a key keep accepting legacy unsigned ingest — boot logs the count. Rotation AND revocation invalidate the cached gate decision in-process immediately (`KeyGate.Invalidate`); revoking (`/keys` Revoke button, `POST /keys/revoke`) drops a project back to unsigned legacy admission — the escape hatch when a producer cannot present a key. URL-native senders that cannot set custom headers (the xhprof extension posting from its endpoint userinfo) authenticate as HTTP Basic: the PASSWORD segment carries the key. The TCP 9913 leg has no header and stays unsigned.
- **Alerts are file-configured and inert without `-alerts-config`**: rules (new-issue, regression [auto-reopen + alert], count-window, p95-latency, heartbeat) evaluate on a tick against aggregates, never per-event; `alerts_log` records only successful sends, so a failed channel retries next tick and cooldowns (default 60m per rule+target) plus per-channel hourly/daily caps bound the storm. No alert UI in M4 (M6 settings pages).
- **Job, release and user-impact telemetry (#158, M5)**: `POST /ingest/{project}/job` batches runs into one aggregate row per (project, kind, name) via an optional `count` (queue producers window 60s in-process; commands ship per run because schedule:run is a short-lived process and the heartbeat rule reads `last_ok_at`); `job_stats` is bounded by name count and covered by retention. `releases` is HARD-CAPPED at the newest 100 rows per project on every insert. The heartbeat rule `{command, cadence_seconds, grace_multiplier}` (default ×2) never fires before monitor boot + one full window and re-alerts only past cooldown. `occurrences.user_id` stores the raw opaque id ONLY (Sentry `event.user.id` or top-level `user_id`) — never email/name; UI renders COUNT(DISTINCT) as "users affected". Crash-free per release is a CONSERVATIVE upper bound (full-volume errors ÷ sampled requests) and must always be labelled a sampled estimate (#158).
- **Ingest wire contracts are compat-locked**: `POST /ingest/{project}/sentry|profile|error|xhprof`, `/api/{project}/store|envelope` (Sentry SDK), `/api/profiler/store` (spiral profiler), TCP 9913 (Monolog newline-JSON) and `GET /up` must never change shape — producers live in other repos (Laravel `MonitorClient`, SvelteKit `lib/server/monitor.ts`) and ship against these paths ().
- **Grouping fingerprints are frozen**: `store.ForException`/`ForLog` normalize volatile tokens; changing the algorithm re-groups every existing issue on deploy — treat both functions as release-pinned ().
- **The store must stay bounded**: `RunRetention` (age-prune occurrences, cap 50/issue, keep newest 5000 profiles) runs on the background ticker from `cmd/monitor`; never delete issues (the defect list is the history), never run retention deletes in a request path, and keep every prune chunked — the SQLite connection is single-writer and shared with ingest.
- **Migrations are additive and idempotent**: new columns/indexes are applied at boot in `migrate()` and must ignore only `duplicate column`/`already exists` errors; never drop or rename (Expand/Contract).
- **Cross-service trace context accepts W3C `traceparent`**: `TraceIDFromRequest` resolves a trace id most-specific-first — the payload's own value, then `X-Monitor-Trace-Id`, then a validated `traceparent` — so an OpenTelemetry-instrumented Go/Python/Rust service joins a trace with header propagation alone and no Nightpost client. `ParseTraceparent` REJECTS a malformed header instead of salvaging it (wrong length, uppercase hex, version `ff`, an all-zero trace id), because a guessed trace key silently groups unrelated requests; an absent trace id stays empty and is never invented.
- **The health contract is two endpoints with different jobs**: `GET /up` is LIVENESS and deliberately never touches the database — a sick store must not get the container killed and restarted into the same sickness — while `GET /ready` is READINESS and runs a real `Store.Ping()` query, answering 503 with the error when the store is gone. Both are unauthenticated, so both stay minimal: `{status, db, revision}`, never a tenant count. Compose/ingress health checks must therefore point at `/up`, and an orchestrator that gates traffic on readiness points at `/ready`.
- **CORS is opt-in and PER PROJECT**: only the first-party error/profile endpoints honor an allowlist, and that allowlist lives on the project row (`projects.cors_origin`) with `-cors-origin` as the install-time seed for a row that is empty — one global string cannot express a multi-tenant install whose tenants each have a different front-end origin. Preflight has its own `OPTIONS` registration because a POST pattern never matches preflight. The request's OWN `Origin` is matched (case-insensitively) against the list and echoed; an Origin that is present but absent from the list is refused **403**, never answered without headers, so the failure is countable. A wildcard is rejected outright at the form (`store.NormalizeCORSOrigins`), because these routes accept unauthenticated browser posts. Default off — server-only senders need no CORS headers.
- **UI stays hydrate-free**: server-rendered SVG (sparklines, waterfall, bars), meta-refresh only on the log stream, no client state — interactive JS belongs in the producer repos, not here.
- **Dashboard views compose from grouped passes, never per-project fan-out**: the all-projects dashboard draws every project's figures from `DashboardSummaries` (ONE windowed `occurrences JOIN issues` pass GROUP BY project/type/hour-bucket + two small issues-table passes + the index-driven per-project `RequestStats`) — re-adding a per-project `HourBuckets` loop re-walks the whole 24h range once per figure and put the dashboard at 28s under real volume (). Lists that surface pain must default to pain order (`count DESC` for issues, total-time for profile routes), not recency.
